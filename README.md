# RSVP читалка

Локальна читалка для швидкого читання методом RSVP: по одному слову в центрі екрана, червона ORP-літера на мітці (як у Spritz). Працює на Windows-ноуті, сервер слухає лише `127.0.0.1:8765`.

## Запуск
`start.bat` → відкриється браузер з бібліотекою. Закрити вікно консолі = зупинити.
Параметри `server.py`: `--open` (відкрити браузер), `--port N` (інакше `port` з `config.json`, типово 8765), `--log-file шлях` (журнал у файл, а не в консоль).

## Відкриття книги
Формати: PDF, EPUB, FB2, MOBI, XPS, CBZ (PyMuPDF), DjVu (`djvutxt`).
- «Відкрити книгу…» на головній — системний діалог вибору файлу. Діалог стартує в теці останньої відкритої книги, інакше на Робочому столі. Він може відкритися за вікном браузера — дивіться панель задач.
- Або з Провідника, див. нижче.
- Головна — «Нещодавні книги»: до 50 записів, нові зверху, у `recent.json` (не в git). Файл, якого вже нема на місці, показано сірим; × прибирає запис зі списку, сам файл лишається.
- Адреса книги — `http://127.0.0.1:8765/#book=<id>`, де `id` = перші 16 символів `sha1(шлях)`. Шлях у адресу не потрапляє. Прогрес у `localStorage` прив'язаний до того ж `id`.

## Відкрити з Провідника
Один раз для свого користувача (без прав адміністратора):
```
venv\Scripts\python explorer_integration.py install --dry-run   # показати, що буде записано
venv\Scripts\python explorer_integration.py install
venv\Scripts\python explorer_integration.py uninstall           # скасувати
```
- Пише лише в `HKCU\Software\Classes`: ProgID `RSVPReader.Book`, запис у `<розширення>\OpenWithProgids` для `.pdf .djvu .djv .epub .fb2 .mobi` і пункт контекстного меню `SystemFileAssociations\<розширення>\shell\RSVPReader`.
- Програму за замовчуванням для розширення не змінює.
- Перед записом зберігає `explorer_install.json` (не в git): створені розділи, записані і попередні значення. `uninstall` скасовує рівно цей список і перейменовує маніфест на `explorer_install.uninstalled.json`.
- Розділи й значення читалки (`RSVPReader.Book`, `...\shell\RSVPReader`, `RSVPReader.Book` в `OpenWithProgids`) `uninstall` видаляє, а не «відновлює»: старе значення там — це наш попередній install.
- Значення, яке після install змінив хтось інший (наприклад, install з іншої теки), `uninstall` лишає і пише про це. Повторний `uninstall` після часткового збою доробляє решту.
- Після install книга відкривається так:
  - ПКМ → «Відкрити за допомогою» → «RSVP читалка»;
  - у Windows 11 — ПКМ → «Показати додаткові параметри» → «Читати в RSVP».
- Верхнє (компактне) меню Windows 11 приймає пункти лише від підписаного пакета (MSIX + `IExplorerCommand`). Цього не зроблено.
- Команда — `venv\Scripts\pythonw.exe open_book.py "<файл>"`. Лаунчер перевіряє сервер (`GET /api/books`, 1 с). Якщо сервер не відповідає — запускає `pythonw server.py --log-file logs\server.log` у фоні й чекає до 15 с. Далі `POST /api/open` і браузер на `#book=<id>`.
- Сервер, запущений лаунчером, не має вікна. Зупинити: Диспетчер задач → `pythonw.exe`. Помилки лаунчера — у `logs/open_book.log` і у вікні повідомлення.
- Перенесли теку проєкту → повторіть `install`: команда містить абсолютні шляхи.

## OCR сканів
Книга без текстового шару (скан PDF / DjVu) показує кнопку «Розпізнати текст (OCR)». Розпізнавання йде у фоні з прогресом; результат кешується, книга далі відкривається як звичайна.
- Tesseract 5, мови `rus+ukr+eng`, 300 dpi, паралельно `cpu_count/2` процесів (до 16).
- Замір 2026-10-17: 0.62 с/стор. на 16 процесах, DjVu на 472 стор. ≈ 5 хв.
- Кеш посторінковий: `cache/ocr/<sha1(path|size|mtime)>/NNNN.txt`. Перерваний OCR продовжується з місця зупинки; збійна сторінка лишається порожньою і повторюється на наступному запуску.
- Одночасно розпізнається одна книга.

## Керування
Кнопки: ⏪ стор · ¶◀ · ⏮ реч · ◀ сл · ▶/⏸ · сл ▶ · реч ⏭ · ▶¶ · стор ⏩; гл◀ [список глав] ▶гл; швидкість − [поле] +; розмір слова A− [px] A+ (24–120 px).
Клавіші: Пробіл — пуск/пауза · ← → — речення · Shift+← → — слово · [ ] — абзац · PageUp/PageDown — сторінка · Shift+PageUp/PageDown — глава · ↑ ↓ — швидкість ±25 слів/хв · + − — розмір · Esc — бібліотека. `[` `]` працюють і на кириличній розкладці (за фізичною клавішею).
Прогрес і швидкість зберігаються в `localStorage` браузера для кожної книги, розмір шрифту — один на всі книги.
На паузі під словом видно весь поточний абзац (до ~120 слів) і назву глави над ним. Клік по слову — перейти до нього.

## Глави й абзаци
Глави показано мітками над повзунком прогресу і списком `гл◀ [глава] ▶гл` (підрозділи з відступом). Книга без глав ховає ці елементи.
- Джерела глав, за пріоритетом:
  1. Зміст файлу: PyMuPDF `get_toc` (PDF/EPUB/FB2/MOBI) або `djvused print-outline` (DjVu; береться лише ціль `#N` — номер сторінки).
  2. Нема змісту — евристика заголовків: короткий окремий абзац, що починається з «Глава / Розділ / Раздел / Частина / Часть / Chapter / Part» + номер або слово, до 10 слів. Номер — арабський або римський, зокрема кириличними літерами («Розділ ІІ.»).
- Фільтри евристики:
  - відкидає надрукований зміст — 3+ заголовки одного виду з різними номерами, якщо:
    - сусідні ближче ніж 40 слів, або
    - сусідні ближче ніж 300 слів і більшість із них далі в тексті трапляється знову (зміст із підрозділами);
  - перший заголовок після змісту з номером, що вже є у змісті (справжня «Глава 1»), — не частина змісту;
  - відкидає колонтитули: повтор того ж заголовка (вид + номер) після першого;
  - після «Частина / Part» нумерація глав починається знову, лише якщо перша глава після неї має той самий номер, що й перша глава книги;
  - заголовок без номера не може закінчуватись як речення (`.!?…`).
- Абзаци:
  - межа — порожній рядок;
  - на сторінці без порожніх рядків — короткий рядок (< 0.8 медіани довжини), що закінчується на `.!?…:»"”`;
  - перший абзац сторінки продовжує попередній, якщо та сторінка не закінчилась розділовим знаком.
- PyMuPDF не дає порожніх рядків між абзацами. Тому текстові блоки сторінки склеюються через порожній рядок. Якщо ≥80 % блоків мають один рядок (OCR-PDF), діє правило коротких рядків.
- Нема абзаців — `[ ]` і ¶ переходять на речення.
- Обмеження DjVu: `djvutxt` не має порожніх рядків, тому абзаци DjVu — лише за правилом коротких рядків. Зміст у DjVu буває рідко: у DjVu-файлах, перевірених 2026-10-17, його не знайдено. Номер сторінки з `#N` приблизний, бо `djvutxt` пропускає порожні сторінки.
- Скан після OCR: глави — зі змісту файлу (якщо є) або евристикою по тексту OCR. Шум розпізнавання дає хибні й пропущені заголовки.
- Замір 2026-10-17 на 61 книзі з Робочого столу:

  | Джерело глав | Книг |
  |---|---|
  | Зміст файлу | 25 |
  | Евристика | 5 |
  | Без глав | 24 |
  | Скан без тексту | 7 |

  DjVu Крешкова після OCR (472 стор.): 6307 абзаців, 13 глав (евристика).

## Залежності
- Python 3.13 venv: `py -3.13 -m venv venv` → `venv\Scripts\pip install pymupdf==1.27.2.3`
- DjVuLibre 3.5.29: `scoop install djvulibre`
- Tesseract-OCR 5.4 (UB Mannheim build) у `PATH` або в `C:\Program Files\Tesseract-OCR\`.
- Мовні моделі в `tessdata/` (не в git): `eng`, `rus`, `ukr` `.traineddata` з https://github.com/tesseract-ocr/tessdata (гілка `main`).

## Рішення
- Текст дістає Python (PyMuPDF / djvutxt), браузер лише показує: pdf.js з `file://` блокує воркери, а DjVu у браузері без сервера не читається.
- `djvutxt` пропускає сторінки без тексту (418 сторінок → 414 `\f`), тому номер сторінки DjVu приблизний (`стор. ~N`), позиція в словах — точна.
- Розбиті переноси `¬\n` (DjVu) і `-\n` + мала літера склеюються; рядки-номери сторінок відкидаються.
- Таблиця ORP (довжина → індекс літери) звірена з кадрами еталонного відео (`tests/rsvp-core.test.mjs`).
- Кеш витягу — `cache/<sha1(path|size|mtime|EXTRACT_VERSION)>.json`; змінив очистку → підніми `EXTRACT_VERSION` у `server.py`. Сирий OCR-текст від `EXTRACT_VERSION` не залежить, тому підняття версії не запускає OCR заново.
- OCR = Tesseract, а не Windows.Media.Ocr: у вбудованому OCR Windows немає української.
- Усі `POST` (`/api/ocr`, `/api/open`, `/api/pick`, `/api/recent/remove`) відхиляють запит із чужим `Origin`, а всі запити — з чужим `Host`. Так сторінка іншого сайту не запустить важку роботу і не додасть файл до списку.
- Список книг — «нещодавні», а не сканування тек: сканування Telegram Desktop (~2000 файлів) і Робочого столу повільне і показує зайве.
- Діалог вибору файлу — tkinter у власному потоці. Сервер сам не має вікна, а браузер не віддає сторінці повний шлях до файлу.
- Скан із повним OCR-кешем після підняття `EXTRACT_VERSION` збирається з `cache/ocr/` без Tesseract.

## Відомі обмеження
- `id` книги — від шляху як рядка. Той самий файл, відкритий за шляхом в іншому регістрі (`C:\Users\...\Book.pdf` і `c:\users\...\book.pdf`), отримує інший `id`: окремий запис у «Нещодавніх» і окремий прогрес. Формулу `id` не змінено, бо зміна скинула б збережений у `localStorage` прогрес усіх книг.
- Евристика глав бере текст як є. Помилки текстового шару дають хибні заголовки: у «Програміст-прагматик» «Глава 5» прочитано і як «Глава S», а рядок коду — як «Part 1».
- Сервер не стартує, якщо порт уже зайнятий (наприклад, друга копія): рядок `cannot listen on ...` у `--log-file` (без нього — у консолі), код виходу 1. Сервер, запущений з Провідника, пише в `logs\server.log`.
